## 2. The findings

### P0. What blocks everything else

**P0-1. There is not a single commit.**
The remote exists, the work is substantial, the history is empty. Three immediate
consequences. First, the SOW evidence of a public repository does not exist at all.
Second, CI has never run once, so everything written in `ci.yml` is still a
hypothesis: `go mod tidy -e`, the `conformance` job with `continue-on-error`, and
`golangci-lint-action@v6` installed against a `version: "2"` config. Third, all the
work of the first three sessions lives on one disk.

**P0-2 and P0-3. `internal/depth` is empty, so the golden fixture tests nothing.**
`internal/conformance/golden_test.go` already fixes the red zone's API surface:
`MidPrice`, `ComputeDepth`, `ComputeManipulationCost`, `ComputeAssetRisk`. Those
four signatures are a contract waiting to be filled. Until it is, the only
safeguard this methodology has is dead, and every new decision is taken without
feedback.

### P1. A forked specification

**P1-1 to P1-3. The migration directly contradicts the TDD, and the table the API uses does not exist.**
TDD section 5 states flatly that "raw snapshots are not stored in the database",
then defines `assets`, `metrics`, and `runs`. `migrations/0001_snapshots.sql` does
the opposite: it stores `raw JSONB` plus a normalised levels table, and has no
`metrics` at all. `keel serve` is designed to read results already computed. The
table for those results does not exist.

**P1-4 and P1-5. `CHECK source IN ('horizon', 'hubble')` will reject a legitimate row.**
`domain.DataSourceTradesImplied` already exists, DEC-002 requires the value to
exist, and the API contract already carries it. The first insert using it fails at
the constraint.

**P1-6 and P1-7. `oracleResistance` is a scalar in the code, an object in the contract.**
`types.go` holds it as `*decimal.Decimal`. DEC-003 section 2.5 explicitly rejects
the scalar form, for a good reason: a ratio hides a `genuineVolume` of zero and
hides `reachable: false`. One of the two has to give way, and it is the contract
that has the written reasoning.

**P1-8 to P1-12. The most important number in this methodology cannot be seen through the API.**
Three fields exist in the code and not in the contract:
`costToMaxReachablePrice`, `unevaluatedFlags`, and `bandConfidence`. The fixture
calls the first of these "the most important line in the whole fixture", because
the real attack landed in the gap between delta 0.5 and delta 1 and only that pair
of numbers caught it. The other two are required by `09-flag-dan-band.md` section
8, and their absence is already admitted inside a warning of the
`assetBrokenBook` example. A contract that admits it is incomplete cannot be
frozen.

**P1-13 and P1-14. The critical delta has two values.**
The contract and every example use `criticalDelta: 0.5`. Methodology section 9
writes `P_critical = 2 x P0`, which means delta 1, and `DefaultParams()` uses 1.0.
On the USTRY fixture this choice determines the result rather than being a matter
of taste: delta 0.5 gives a zero cost with `Reachable = true`, while delta 1 gives
`Reachable = false`. `C_max` and `oracleResistance` change with it.

**P1-15. `C_max` loses half of its output.**
Methodology section 9 requires both terms to be reported, not only the minimum, and
states why: an asset can pass the liquidation limit and fail the manipulation
limit, and that distinction is Keel's main differentiator from the monitoring tools
that already exist. `types.go` and the contract carry only the minimum.

**P1-16 to P1-19. One directory with no owner, containing float64.**
`internal/adapter/horizon.go` uses `float64` in two places, including
`NormalizePrice`, which inverts a price through `1.0 / raw` when
`domain.Price.Invert()` already does the same thing exactly. No package imports it,
so it is dead code. `arch_test` does not reach it because `paketMurni` holds only
`.` and `../depth`. And `internal/adapter` appears in neither the `CLAUDE.md` zone
map nor the TDD zone table, so by the repository's own rules it is a directory
without an owner.

**P1-20 and P1-21. The headline number of Deliverable 2 is wrong, and the evidence that fixes it is already in the repository.**
DEC-001 writes "one source states the trade that executed it was worth about $0.50"
and derives a ratio of 1 to 22 million. `docs/evidences/spike_result_final.txt`
holds that trade: **5.3475699 USDC exchanged for 0.0501003 USTRY** at 106.7372828,
ledger close 2026-02-22T00:10:21Z. Against roughly 10.97 million dollars borrowed,
the ratio is about **1 to 2.05 million**, not 1 to 22 million. The premise still
sells with the correct number. What must not happen is an SCF reviewer opening
Horizon and finding a tenfold discrepancy in the opening number of the report.

**P1-22 to P1-24. Two curl procedures in the decision records give USTRY the wrong type.**
DEC-001 section 5.2 and DEC-002 section 3 use
`base_asset_type=credit_alphanum4` for USTRY, which is `credit_alphanum12`. The
evidence is in this repository. This is exactly the silent failure `types.go` warns
about: Horizon returns an empty result and no error message. Anyone following those
procedures will conclude the USTRY/USDC market has no trade history.

**P1-25. The DEC-002 spike DoD is unmet, and the evidence is capped at one page.**
All three evidence files stop at exactly 200 and 204 records, which is Horizon's
`limit=200` cap, with no pagination. The first file is also sorted descending, so it
starts at 19 August 2026, meaning its contents are the last 200 trades rather than
"the full trade history" as its comment claims. The DoD question "how many trades
exist across this market's entire history" is therefore unanswered, and revisit
condition 1 in DEC-002 section 6 cannot be assessed.

**P1-26 and P1-27. DEC-003 preserves a mistake that its own contract has already corrected.**
The table in DEC-003 section 4 lists `MC(delta=1)` as `reachable: true`. The API
contract has already corrected it to `false` and even carries a dedicated paragraph
saying it is "exactly the mistake that point 7 warns about". The decision record now
holds the wrong version. DEC-003 is also still marked DRAFT even though two of its
four freeze conditions are done.

**P1-28 to P1-31. Two small contract errors that an outsider sees first.**
`documentUrl` points at `github.com/ciganytry/keel` and at the file
`00-ikhtisar.md`. The org is `Keel-Official`, and that file does not exist, so the
official link to the methodology document in the `/methodology` response is broken
twice over. Then `assetBrokenBook` uses
`ledgerClosedAt: 2026-02-21T23:39:00Z`, when ledger 61340263 closed at
2026-02-22T00:10:21Z. The evidence pins this from two directions: the fixture uses
that time, and ledger 61340272 closed at 00:11:16, nine ledgers later.

**P1-32 and P1-33. The golden fixture declares a provenance that contradicts the contract.**
`GoldenSnapshot()` labels itself `DataSourceHorizon`. The contract and DEC-003
section 2.6 label the same book `trades-implied`, for a firm reason: that book was
reconstructed from on-chain operations rather than read from an orderbook snapshot,
so its depth figures are lower bounds and must carry a warning.
`TestMetadataWajib` will lock in whichever value is chosen, so this has to be
decided before `internal/depth` is written, not after.

## 3. Two questions for the red zone

I do not write in `internal/depth`. These two are what I found as a questioner, and
both are better answered before the formulas are coded.

**Question 1. The cost of the final touch is not zero in reality.**
Methodology sections 7.1 and 7.2 are right that an attacker only needs to touch the
first ask above the target, and that the touch can cost arbitrarily little. That is
why `Cost(delta=0.5)` is zero on the fixture. But the real attacker paid 5.3475699
USDC, not zero, and the reason is not the marginal touch cost; it is that what has
to be moved is the VWAP inside the oracle window, not the marginal price. No Keel
quantity reports that 5.35 figure. `OracleResistance` in section 8 comes close with
`MC + V_genuine(W)`, but it does not yield a "minimum trade size needed to dominate
the window". Is 5.35 USDC an empirical anchor that belongs in the methodology, and
if so, as what?

**Question 2. `CostToMaxReachablePrice` is zero structurally, not specifically.**
Its definition sums the asks with `price < MaxReachablePrice`. For a book with a
single ask the value is zero for any asset, healthy or broken. So "reaching the
highest price on this book is free" on USTRY is a consequence of the book's shape,
not a finding about USTRY. That remains consistent with section 7.1, and perhaps
that is the intent. The question: what makes this number informative when reported
on its own, and does it need to be accompanied by the ask level count so a reader
knows which kind of zero it is?

## 5. How to review this work

Four layers, cheapest first.

**Layer 1, thirty seconds. Run the verification script.**

Forty four lines, each mapping one claim in this document to one command that runs

**Layer 2, two minutes. Check the fixture arithmetic I claim is correct.**

One bug was found while staging, and it nearly slipped through. `.gitignore` held

The single entrypoint of this project would have vanished from the repository with

**The suspicion about the lint job became a fact.** On the first CI run the
`golangci-lint` job failed with a legible cause:

```
Command failed: golangci-lint-1.64.8-linux-amd64/golangci-lint config verify
jsonschema: "linters" does not validate: additional properties 'settings' not allowed
jsonschema: "" does not validate: additional properties 'version', 'formatters' not allowed
```

`golangci-lint-action@v6` installs golangci-lint **1.64.8**, a v1 binary,
regardless of `version: latest`. A v1 binary rejects a `.golangci.yml` written for
v2, because `version`, `formatters`, and `linters.settings` are v2 keys. The fix is
one line: raise the action to `@v7` or later. Filed under T7.

Another consequence worth recording: because the lint job had never actually run,
the lint findings on `internal/adapter` had never been seen either. The suspicion
waiting to be tested once the action is raised: `priceRatio.float()` is used by
nobody and will be caught by the `unused` linter. That is material for T2.

**About the red zone hook.** The old lock only denied `Edit` and `Write` on the red
zone, which left Bash wide open. There is now
`.claude/hooks/lindungi-zona-merah.sh`, a `PreToolUse` hook that refuses
file-mutating Bash commands mentioning that zone. It was tested against 21
commands, 9 that must pass and 12 that must be refused, and all were correct. The
P2-6 check in the verification script now runs that hook with a synthetic payload,
so if the hook is removed or breaks, the line returns to PROVEN.

Two things must be recorded honestly about that hook. First, it lets reads through,
so `cat`, `ls`, `grep`, and `go test ./internal/depth/` still work, including with
`2>&1`. Second, it is biased toward refusing: a file-mutating command that mentions
the zone's name is refused even when its real target is outside the zone. That
happened once while T7 was being done, when the verification script itself was
about to be edited through Bash. The way out is not to weaken the hook but to use
`Edit` for files outside the red zone, which permissions already govern separately.
This is a guardrail, not a sandbox.

**Three findings that surfaced during the translation, not yet in the numbered list
above.**

1. **The repository was renamed** to `Keel-Official/keel-backend` mid-session; the
   push reported the redirect. The git remote and the documentation references were
   updated. The Go module path is still `github.com/Keel-Official/keel` and was
   deliberately left alone, because changing it touches `go.mod` and six import
   lines and is a separate decision.
2. **Two synthetic issuer addresses in the contract examples are invalid.** The RWAX
   and USTRY/XLM examples are 60 characters long and contain 0, 1, 8, and 9, none of
   which are in the Stellar base32 alphabet. Both violate the `G[A-Z2-7]{55}`

   example validator would reject them and a frontend developer copying one into a
   test gets an invalid asset id. Material for T6.
3. **PRD section 5 is stale in a way that matters.** `09-flag-dan-band.md` declares
   that it supersedes PRD sections 5.1 and 5.2 and that the PRD now only points
   there, but the PRD still carries full flag definitions, and its version predates
   `SPREAD_EXTREME` and the three-state flag model. Two homes for one definition,
   exactly the failure mode both documents warn about.
